FaB Paxos example execution: Byzantine acceptor tolerated
=========================================================

Scenario: one Byzantine acceptor a1, the rest correct, two values {v0, v1}, one
term (MaxPN = 1). The Byzantine baseline (injected at Init) has a1 equivocating:
it sends ACCEPTED for both v0 and v1. The run shows the correct acceptors
forming a quorum on the leader's value while a1's conflicting vote is tolerated.

How produced: TLC breadth-first search, the shortest run that violates the
read-only observer NeverLearned defined in MCFaBPaxosTrace.tla. The protocol in
FaBPaxos.tla is unmodified. The state blocks below are TLC output, verbatim. The
full untrimmed log is in byzantine.raw.txt.

Command (run from spec/):
  java -jar ~/tools/tla2tools.jar -fp 1 -config traces/byzantine.cfg MCFaBPaxosTrace.tla

Reading: learner l1 decides v0 on a fast quorum of five ACCEPTED for (v0, 0):
four from correct acceptors a2, a3, a4, a5, plus one from the Byzantine a1. This
is exactly why FaB needs 5f + 1: a fast quorum of five can include up to f = 1
Byzantine vote and still contain four correct acceptors, which meets the chosen
threshold ceil((a + f + 1) / 2) = 4. a1's conflicting ACCEPTED for v1 forms no
quorum, so v1 is never chosen or learned. Safety holds; the fault is tolerated.
