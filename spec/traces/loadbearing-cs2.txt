FaB Paxos counterexample: certificate check removed (load-bearing test)
=======================================================================

WARNING: this is an execution of a DELIBERATELY BROKEN variant, not the real
protocol. We temporarily removed the acceptor's VouchedAtPN check in the Accept
action of FaBPaxos.tla, so a correct acceptor would switch to any higher-pn
proposal without a progress certificate. We ran the safety config with the
Byzantine leader active, captured this counterexample, then reverted the change.

Purpose: this shows the progress-certificate check is load-bearing. Without it,
the Byzantine leader's poisonous write succeeds: a value is chosen at the first
term, the Byzantine proposer becomes leader, proposes a different value at the
next term, and correct acceptors accept it, so a second value is chosen and CS2
fails. With the check in place (the real spec), this attack does not work.

How produced: safety config (MCFaBPaxos.cfg) with the VouchedAtPN branch removed.
Full untrimmed log: loadbearing-cs2.raw.txt.

----------------------------------------------------------------------
